# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Build & Development

```bash
# Build
go build -o atlassian-cli .

# Run tests
go test --shuffle on --race -v ./...

# Run tests for a specific package
go test ./internal/htmlconv/...

# Run a single test
go test ./internal/htmlconv/ -run TestConvert

# Lint
golangci-lint run
```

## Architecture

The project is a single Go binary (`main.go` → `cmd.Execute()`) structured as a CLI + MCP server.

### Package layout

- **`cmd/`** — Cobra command tree. Each file corresponds to a command group (e.g., `jira_issue_get.go`, `confluence_page.go`). Commands instantiate an API client, call it, and delegate rendering to `internal/formatter`.
- **`internal/config/`** — Reads `JIRA_*` / `CONFLUENCE_*` environment variables, falling back to shared `ATLASSIAN_*` ones (a shared email is only paired with an API token, never a PAT). If `EMAIL` is set, Basic auth (Cloud) is used; otherwise Bearer auth (Server/DC). `LoadJiraConfig()` / `LoadConfluenceConfig()` are the entry points.
- **`internal/browser/`** — `Open(url)` launches the platform's default web browser (`open` / `rundll32` / `xdg-open`) without waiting; used by `issue open`, bookmark `--web`, the TUIs' `o` and cross-links.
- **`internal/httpclient/`** — Thin HTTP client wrapper that injects auth headers. `Transport()` (`tls.go`) is the shared RoundTripper for real servers, also used for page images: the default transport plus `ATLASSIAN_CA_FILE` roots (system pool + file; on macOS Go retries with its own verifier when the platform one fails).
- **`internal/jira/`** — Jira REST API client and type definitions (`types.go`).
- **`internal/confluence/`** — Confluence REST API client and type definitions (`types.go`).
- **`internal/formatter/`** — Renders API responses in three formats: `table` (tab-aligned), `json`, `markdown` (plus `csv` for issue lists; `columns.go` holds the selectable issue columns). HTML content is piped through `htmlconv.Convert()` when using markdown format.
- **`internal/mdconv/`** — Markdown → Jira wiki markup (`ToJiraWiki`, goldmark AST walk) and Markdown → Confluence storage (`ToStorage`, goldmark HTML renderer with custom nodes for code/admonition macros and images; ```` ```storage ```` fences pass through). `ToStorage` is the inverse of `htmlconv.Convert`; `TestStorageRoundTrip` guards that. CLI and MCP convert text with these unless `--raw` / `body_format: storage`.
- **`internal/htmlconv/`** — HTML-to-GFM converter (`Unsupported()` lists storage features a Markdown round trip would lose; `confluence page edit` refuses such pages). Handles standard HTML tags plus Confluence storage format macros (`ac:structured-macro`, `ac:link`, `ac:emoticon`, etc.). This is where macro rendering logic lives. Task lists render as GFM task items; page links as `[title](#)` (no URL: a mirror's base leads nowhere); mentions (`ri:user`, key only) as `@Name \<email\>` through `ConvertWith(…, Options{User})` — `confluence.ResolveMentions` (`/rest/api/user`) supplies it in the page browser and `page get --content-only`; the mirror serves that endpoint from user objects in its pages/attachments plus each page's `users.json` (written by export for the mentioned users).
- **`internal/mcptools/`** — MCP server implementation using `github.com/modelcontextprotocol/go-sdk`. `groups.go` maps group names to tool names (`optInGroups` are only enabled when named); `server.go` creates the server and registers tools via `maybeAdd()`. `compact.go` holds the default compact result shapes (`full: true` returns raw API objects). Every new tool must be added to a group — `TestToolGroups` checks it.
- **`internal/tui/`** — Bubbletea-based interactive issue browser for `jira issue search` (auto on a TTY, `-i` forces, `--plain` disables). The model talks to Jira through the `tui.Source` interface (implemented by `*jira.Client`), so refresh/transition/detail loading happen inside the TUI; tests drive `Update` against a fake source. `explorer.go` wraps that issue model as the right pane of a two-pane explorer (feature/epic/sprint commands in `cmd/jira_explorers.go`; `issuesLoadedMsg.jql` drops stale results when the selection changes); `pagetree.go` is the Confluence page browser (`confluence browse`). `issuefilter.go` (issue list), `pagefilter.go` (page tree) and the bookmark browser share the `/` fuzzy finder (`filterBox`, `highlight`/`matchStyle`; filtered issue lists are drawn by `filteredView`, since bubbles/table cells cannot hold highlights); `pagefilter.go` is the page tree's (`fuzzy.go` matcher; opening it loads whole spaces via `SpaceTreeSource` and merges them into the tree). `pageimages.go` downloads a page's images (attachments via `ImageSource`) and draws them in place by replacing `@@imgN@@` markers after glamour rendering; `i` hands the terminal to `termimg.Preview` through `tea.Exec`. A downloaded "image" that is a PDF (htmlconv renders the `viewpdf` macro as `![name](escaped name)`) becomes a deck: `renderSlides` (`pdfslides.Render`) gives one PNG per page, `pageImage.slides`/`slide`, `[`/`]` (`turnSlide`, on `currentDeck`: the first deck in view) decode the next one; `gen` drops kitty transmissions of a slide no longer shown; `i` lists every slide as lazy `PreviewItem.Load` items. The issue detail view has the same `i` (`issueimages.go`): `issueImageRefs` orders Xray step evidence, run evidence, step attachments, image attachments; downloads go through the source's optional `DownloadAttachment` (`attachmentSource`), decoded images are cached per issue; image support is detected before the program starts (`newGraphics`, in `RunIssueList`/`RunExplorer`, which also run with `termimg.Output`). The detail view also draws images in place (`issueinline.go`): `issueMarkdownWith(…, true)` embeds them (`xray.MarkdownEmbed` after each Evidence line, an Attachments section), then the page browser's pipeline, shared as plain functions in `pageimages.go` (`extractImages` → glamour → `placeImages`, `kittyTransmitCmd`); `issueInline` per loaded issue (pointer identity drops stale results), kitty images deleted on refresh/exit; `fetchInline` sends credentials only to site URLs. `l` (`issuelinks.go`, `modeLinks`) lists `issueLinkItems` — parent (`IssueFields.Parent`), Epic Link (by name), issue links, subtasks, `xray.CoverageTests`, then keys mentioned in description/comments limited to already related projects — and follows one; `detailTrail` makes esc walk back before returning to the list; a failed load of a followed key steps back with a status. Cross-links (`crosslinks.go`): with `Options.OpenPage` set (cmd wires it only when Confluence is configured, `cmd/crosslinks.go`) `l` also lists `issuePageItems` — Confluence remote links (`remoteLinkSource` → `jira.Client.LoadRemoteLinks`; `globalId` pageId when the URL is on another host) then page links in description/comments/custom fields under `PageBases`; the page browser's `L` (`treeLink` entries) lists `xref.IssueRefs` of the shown page, then the keys of its issue lists (both only with `TreeOptions.OpenIssue`/`IssueBases`), then `xref.StoragePageLinks` (`<ri:page>` links, page URLs under `PageBases`); a page is followed in place (`followPage`: by ID via `revealPage`, by title through the source's optional `PageFinder` CQL lookup → `pageFoundMsg`). Issue lists (`issuelists.go`): with `TreeOptions.SearchIssues` (`jira.Client.SearchRaw`) `loadPage` runs each Jira issues macro's query (`xref.IssueQueries`, in parallel) and `preparePage` swaps the macros for HTML tables (`xref.ReplaceIssueQueries`) before `htmlconv.Convert`. The other browser runs in-process in place of this one via `tea.Exec` with a `runExec` ExecCommand (`execCross`, a var so tests capture it); q there returns.
- **tmux navigation** (`internal/tui/tmuxnav.go`): `tmuxSelectPane(dir)` runs `tmux select-pane -t $TMUX_PANE -<dir>` inside tmux (a var for tests). vim-tmux-navigator's bindings (README) hand ctrl+h/j/k/l to atlassian-cli, so views pass them on: ctrl+h/l past the edge of the tree/explorer focus and always in the one-pane issue/bookmark browsers (not the embedded picker); ctrl+j/k (`tmuxPaneKey`) everywhere except filters, which keep them for matches. Copy key is `C` for that reason.

- **`internal/bookmarks/`** — Bookmark store (`bookmarks.yaml` under the user config dir, or `ATLASSIAN_BOOKMARKS`): issues, queries, features, epics, sprints, pages. `Describe` looks items up for title/link (shared by `cmd/bookmark.go` and the `bookmarks` MCP group). TUIs take a `tui.Bookmarker` (`b` toggles, `S` saves a query, `B` opens the bookmark browser embedded as a picker: `newPicker`/`updatePicker`; the page tree reveals a picked page via `revealPage`, loading its space or switching to it; the issue browser resolves feature/epic/sprint bookmarks through `Options.ResolveBookmark`); `tui.RunBookmarks` is the standalone bookmark browser, and `cmd/bookmark.go` loops between it and the opened view.
- **`internal/xray/`** — Xray (Server/DC) test data, recognised by shape since field IDs differ per server: `ManualSteps` (the Manual Test Steps field, two layouts), `RunRefs` (latestId/latestFinalId in TestRunStatus), `Files` (any `fileName`+`fileURL` object: evidence, step attachments), `Markdown` (the Test Details section). `jira.Client.LoadXrayRuns` fills `Issue.XrayRuns` (`/rest/raven/1.0/api/testrun/{id}`, best effort) for `issue get`, the TUI detail view (`xraySource`) and `issue evidence`; the export stores runs as `xray/testrun-<id>.json` + files under `xray/files/` with `xray/urls.json` (site path → file), which the mirror serves at Xray's URLs.
- **`internal/termimg/`** — Terminal images: protocol detection (`Detect`: `ATLASSIAN_IMAGES`, env, tmux client info, XTVERSION/DA1 query), half-block text, kitty Unicode placeholders (`diacritics.go` is generated from kitty's table), iTerm2 and Sixel encoders, tmux passthrough wrapping. `Output` serializes image escape sequences with bubbletea's frames.

- **`internal/pdfslides/`** — PDF pages → PNGs via `mutool draw` (preferred, ~6× faster) or `pdftoppm` (Go has no PDF renderer), cached by content hash under `ATLASSIAN_SLIDES_CACHE` / user cache dir `atlassian-cli/slides/<hash>/` (rendered into a temp dir, renamed into place). Used by the page browser for embedded PDFs.

- **`internal/xref/`** — References between Jira and Confluence: `PageRefs(text, confBases…)` (viewpage.action pageId or spaceKey+title, `/spaces/S/pages/N`, `/display/S/Title`, tiny `/x/` via `DecodeTinyLink`), `IssueRefs(storage, jiraBases…)` (Jira issue macro `key`, `/browse/KEY`, `/projects/P/issues/KEY`), `Strings` (all strings of decoded JSON). Only links under the given bases count. No internal imports; used by mirrorsync and tui.
- **`internal/mirror/`** — Offline mirror: `Server` loads a mirror directory (layout in `mirror.go`; `local/` overlays it) and serves the REST endpoints the clients use, read-only, as an in-process `http.RoundTripper` (`Transport`). `config.loadConfig` switches to it (`mirrorConfig`: base URLs `JiraBase`/`ConfluenceBase`, explorer settings from the manifest) when `ATLASSIAN_MIRROR` is set or no service URL is set and the default directory has `mirror.json`; `httpclient.NewFromConfig` plugs the transport in for those bases, so clients/TUI/MCP are unchanged. Original server URLs in served JSON are rewritten to the mirror bases (so cross-links resolve against the clients' own bases); `remotelinks.json` per issue is served at `…/remotelink`. `query.go` parses JQL/CQL (AND/OR/NOT, ORDER BY, functions); `jql.go`/`cql.go` evaluate them. Issue lists on pages (`jira-queries.json`, `xref.QueryResult`) answer `runJQL` for their exact JQL (whitespace-normalized) before the JQL engine. It must not import other internal packages (httpclient imports it) except the stdlib-only `xref`.
- **`internal/mirrorsync/`** — `mirror export` (raw REST via `Raw`, downloads attachments, writes the layout, tars it; sources: boards, `--jql`, bookmarks, `--page`, plus by default the active sprints of the boards — `activeSprintJQL`, default-project fallback — and `myIssuesJQL`: own issues not resolved as Done/Fixed, naming only resolutions the server has; then `relatedKeys` adds one non-recursive level of relatives: parent, subtasks, `issuelinks` both ways, Epic Link field, and `xray.CoverageTests`: tests in Xray Requirement Status `…Jql` lists, detected by shape since its field ID differs per server; `storeIssue` also saves `remotelinks.json`; finally `exportCrossRefs` crosses the Jira/Confluence boundary one step: pages linked from the issues selected so far (`xref.PageRefs` over every string of issue.json + remotelinks.json, `/display/` refs resolved by title) and issues on the bookmark/`--page` tree pages (`xref.IssueRefs`: Jira issue macro, `/browse/` links) and the issues of their issue lists (`exportPageQueries`: each macro's JQL via `search`, capped by its `maximumIssues` and `maxQueryIssues`, results — failures too — in the page's `jira-queries.json`), whatever `--only` says (import upserts any side's items); the manifest records both URLs whenever configured) and `mirror import` (upsert per issue/page/board/space dir via renames from a staging dir next to the mirror, `--prune` for full snapshots — `keepLinked` spares stale items that a staying item links to —, union-merges bookmarks, never touches `local/`). Embeds (`embeds.go`): `ExportOptions.Embeds` (cmd: `--embeds` → `ATLASSIAN_EMBEDS` → `<config>/atlassian-cli/embeds.yaml`, YAML list of {url, file}) — `exportPage` → `attachEmbeds` → `applyEmbeds` replaces each innermost macro whose `url` parameter contains an entry's URL key (`embedKey`: no query/fragment/trailing /edit…) by `viewpdf` (PDF; `embedded-url` param keeps the original) / `ac:image` / `ac:link` over a synthetic attachment (ID `embed-<sha256[:8]>`, file under `files/`, entry shaped like Confluence's); unmapped `widget` macros are warned about; the PDF alone travels, slides are rendered by the viewer. `--only jira|confluence` exports one side; the manifest's `contents` names the sides an archive covers (empty = both, older archives), import prunes only those and `mirror.MergeImport` updates only their URL/settings/freshness (`Manifest.Jira`/`.Confluence` `SideState`; `Side()` synthesises both from the top-level fields for a pre-split mirror).

### Key design patterns

- **Long text input**: `cmd/body.go` — `addBodyFlags` + `readBody` give a flag, `--template FILE|-`, `-e/--editor`; required text also falls back to piped stdin, then `$EDITOR` on a TTY. Optional text never reads stdin implicitly.
- **Issue lists**: `cmd/issue_list_output.go` — `addIssueListFlags` + `showIssues` shared by `issue search` and `issue list` (TUI vs. formatter decision in `useInteractive`). `jira.BuildJQL` turns `issue list` filter flags into JQL.
- **Errors**: `rootCmd.PersistentPreRun` sets `SilenceUsage` once flags/args validated, so runtime errors print without the usage text.
- **Server/DC vs Cloud**: `jira.Client.cloud` (email set or `*.atlassian.net`) selects user references (`accountId` vs `name`, see `userRef`/`UserID`) and the search endpoint. Shared operation logic (user/link-type/field resolution, clone) lives in `internal/jira/operations.go` and is used by both CLI and MCP.
- **Dev server**: `go run ./tools/devserver -data <dir>` serves exported issues over the REST endpoints the CLI uses (optional `<dir>/names.json` maps custom field IDs to names); never commit real exported data.

- **Output format**: All commands take `--output` / `-o` (table/json/markdown) via a persistent root flag. Commands read it with `cmd.Root().PersistentFlags().GetString("output")`, then call `formatter.ParseFormat()`.
- **Auth dispatch**: `config.loadConfig()` tries `_API_TOKEN` first, then `_PERSONAL_TOKEN`. If `Email` is non-empty in the resulting struct, the HTTP client uses Basic auth; otherwise Bearer.
- **MCP tool filtering**: `mcptools.maybeAdd()` checks `isToolEnabled(name, enabledGroups)` before registering each tool. The `--tools` CLI flag passes a comma-separated list of group names.
- **HTML conversion**: `htmlconv.Convert()` uses `golang.org/x/net/html` to parse, then walks the node tree with `renderElement()`. Confluence-specific tags (`ac:*`, `ri:*`) are handled before standard HTML tags.

## Release

Releases are automated via GitHub Actions (`.github/workflows/release.yml`) triggered on `v*` tags. GoReleaser builds cross-platform binaries for linux/darwin/windows × amd64/arm64.
